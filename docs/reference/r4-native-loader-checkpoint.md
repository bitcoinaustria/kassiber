# R4-9 native custody loader checkpoint

This is an **unaccepted, test-only checkpoint**, dated 2026-10-31, based on
`dd433e4e` plus the R4-1 baseline-record cherry-pick `1f064db49`. The prototype
misses the generic-20k 0.30 s target. The R4 plan requires stopping for
re-planning at a failed target. Python retains every production load and
journal route; this checkpoint does not complete R4-9.

## Implemented boundary

`crates/journals/src/loader.rs` exposes `load(connection, profile, as_of)` only
under tests or the `test-harness` feature. The connection belongs to an already
opened `kassiber_store::Book`. Loading requires an existing SQLite write
transaction, reads pending caller writes, and never begins, commits, rolls
back, repairs or updates the book. A failure leaves caller rollback ownership
intact. Native tests check both success and refusal, including rollback of a
pending canary write.

`LoadedSnapshot` holds ordered `kassiber_pyjson::Value` facts. `v1()` writes
Python's default `json.dumps(..., ensure_ascii=True, allow_nan=True)` bytes.
`into_custody()` moves the facts into today's custody `Snapshot` through
in-memory values, without serializing the snapshot as JSON text. This is a
temporary producer seam for R4-2/R4-3's typed `BookSnapshot`, not the final
typed model. The conversion cost is included in the native total below.

The draft reads network bindings/references, wallet/transaction/rate rows,
active components and their children/anchors/revision headers, the owned
index, receipt sources, channels, live loan legs, evidence snapshots, unresolved
migration issues, latest gap reviews, dismissals and the bounded gap worklist.
Descriptor derivation calls `crates/wallets`' existing R5 implementation;
there is no second derivation engine. Integer msat and SQL INTEGER versus REAL
remain distinct. BLOBs and invalid UTF-8 are refused rather than coerced.
Loading grants no ownership, network consent or tax authority.

Only existing internal path dependencies were added. No new third-party
dependency, package version or runtime requirement was introduced.

`custody-load` is an unregistered example requiring `--features test-harness`.
Its root mode opens plaintext/SQLCipher books through `crates/store`; fixture
mode restores a supplied SQL dump in memory. Only the explicit local test hook
`KASSIBER_TEST_CUSTODY_LOADER_BIN` enables it alongside census/shadow builds.
The hook includes uncommitted writes and compares exact v1 bytes, reporting
only a byte offset on mismatch. The private SQL copy stays on the child pipe;
see [privacy](privacy-and-security.md). It is not enabled by default in CI.

`crates/journals/scripts/generate_loader_vectors.py`; `--check` recomputes
Python's expected bytes. Their permissive historical schema preserves column
defaults while removing constraints. Generation asserts nonempty transactions
and active ownership/receipt branches to prevent empty-snapshot comparisons.

## Timing method

`scripts/benchmark-custody-loader.py` uses disposable books built with
`scripts/journals-bench-books.py`: generic seed 1 and multi-wallet seed 7,
each at 2k/20k.
These four timing books are plaintext; SQLCipher byte coverage is separate.
It checks the complete v1 bytes before timing, excludes book open/BEGIN and
v1 serialization, and includes the temporary native adapter in the total.
Python and Rust run back to back, alternating order for five pairs per book.
Each pair records all three load averages. Best-of-five native totals use
one complete pair, not separately selected load and adapter minima.

| Book | Best Python | Native load | Adapter | Best native total | One-minute load range |
| --- | ---: | ---: | ---: | ---: | ---: |
| Generic 2k | 0.112 s | 0.070 s | 0.059 s | 0.129 s | 21.11–21.47 |
| Multi-wallet 2k | 0.159 s | 0.087 s | 0.071 s | 0.158 s | 21.11 |
| Generic 20k | 1.218 s | 0.739 s | 0.581 s | **1.321 s** | 19.83–21.18 |
| Multi-wallet 20k | 1.471 s | 0.873 s | 0.684 s | 1.557 s | 20.73–21.64 |

The native load alone also misses 0.30 s. The complete native boundary is
slower than Python at 20k. Ordered dynamic records and their second
conversion are not an adequate production implementation of the typed loader.
The SQL floor remains the earlier 0.11 s reference measurement; it was not
remeasured in this run.

The [complete timing records](r4-native-loader-bench.json) retain all twenty
pairs, load averages, generator manifests, byte lengths/hashes and the final
release probe SHA256
`40b977676161500a04b6ee535f6cc703458bec98d1f5e3cdbeded78e5d3b7e4f`.

## R4-13 integration contract

R4-13 must first open through `crates/store`, hold `BEGIN IMMEDIATE` and its
build savepoint, run R4-10 repairs/pricing, and then call the loader with that
same connection, the exact ordered profile mapping and injected `as_of`.
It must consume the eventual typed `BookSnapshot` directly, propagate a
refusal/panic to rollback without refreshing freshness markers, and commit
only after successful persistence. No CLI/daemon/AI route should call this
test-only prototype or make its serializer a production boundary. All
accounting admission and the watch-only/no-egress boundaries still apply.
